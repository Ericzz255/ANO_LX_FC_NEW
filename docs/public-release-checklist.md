# 公开发布检查清单

在把仓库从私有改为公开、向招聘方分享或制作 Release 前，逐项确认：

## 版权与许可

- 确认凌霄飞控基础源码是否允许公开、修改和再分发。
- 不上传厂商手册、题目附件、论文或其他没有再分发授权的材料。
- 对团队原创代码选择许可证；如果无法覆盖全部代码，不要给整个仓库误加开源许可证。
- 在 README 中明确原创模块和第三方基础代码的边界。

## 隐私与比赛资料

- 检查设计报告中的姓名、学号、手机号、邮箱、签名和学校内部信息。
- 检查图片、视频和日志中的人脸、车牌、Wi-Fi、精确位置和设备序列号。
- 不公开仍受比赛规则限制的材料或队友未同意公开的内容。

## 凭据与设备信息

- 搜索 API key、Token、密码、私钥、Wi-Fi 配置和远程登录信息。
- 检查 Git 历史，而不只是当前工作树；已删除的敏感信息仍可能存在于历史提交。
- 检查串口日志和崩溃转储中是否含设备标识或路径信息。

## 仓库卫生

- 移除临时备份目录、重复生成文件、个人 IDE 配置和不必要的二进制文件。
- 保留可复现构建所需的源码、工程配置、协议文档和最小测试数据。
- 将大体积飞行日志和视频放到单独 Release/对象存储，并附校验和与固件版本。
- 确认 `.gitignore` 只阻止生成物，不会把必须的源码依赖意外排除。

## 对外表述

- 区分“源码检查通过”“编译通过”“台架通过”和“实飞验证通过”。
- 不用一次成功飞行代表可靠性；提供测试次数、失败次数和已知限制。
- 不宣称未实际承担的团队工作；在项目说明中标出个人贡献。
