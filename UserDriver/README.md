# 用户外设驱动说明 (UserDriver)

## 1. 项目简介

本工程基于 **匿名科创凌霄飞控 (ANO_LX_FC)**，主控为 **STM32F407**。  
当前任务目标：通过 **CH6 高位** 一键触发，无人机自动完成 **起飞 → 路径规划 → 逐格遍历 → 降落** 的程控飞行流程。USART3 已恢复为树莓派 SLAM 定位数据通道，为后续水平位置闭环做准备。

场地规格：
- 网格大小：**7 行 x 9 列**
- 单格尺寸：**50 cm x 50 cm**（`GRID_SIZE_CM = 50`）
- 障碍物（禁飞区）：`(3,5), (4,5), (5,5)` —— 已硬编码

---

## 2. 硬件连接

| 外设 | 串口 | 用途 |
|------|------|------|
| 树莓派 (Raspberry Pi) | USART3 | 接收 SLAM/N10P 雷达定位数据（`now_x`, `now_y`） |
| USB-TTL 调试器 | USART1 TX（PA9） | 输出通过CRC校验的树莓派坐标 |
| 无线串口模块 DL20 | USART2 | 地面站通信（当前未使用，仅保留接口） |

---

## 3. 通信协议

### 3.1 树莓派定位数据 (USART3)

**帧格式：** `45 53 05 SEQ X_H X_L Y_H Y_L CRC_H CRC_L`

| 字节 | 含义 |
|------|------|
| [0..1] | 双字节帧头 `0x45 0x53` |
| [2] | Payload长度，当前固定为 `0x05` |
| [3] | 帧序号 `SEQ` |
| [4..5] | `now_x`，16位有符号整数，高字节在前 |
| [6..7] | `now_y`，16位有符号整数，高字节在前 |
| [8..9] | CRC16，高字节在前 |

CRC采用 **CRC16-CCITT-FALSE**：初值 `0xFFFF`，多项式 `0x1021`，不反转，无最终异或；计算范围为 `LEN + SEQ + X_H + X_L + Y_H + Y_L`。固定长度解析允许坐标数据中出现 `0x45`、`0x53` 等任意字节，只有长度和CRC均正确时才更新坐标。

**数据消费位置：** `Ano_Scheduler.c` 的 `Loop_50Hz()` 中，每隔 20ms 读取一次，更新全局变量 `now_x`、`now_y`。  
**当前用途：** 更新 `now_x`、`now_y`，暂未参与飞行控制闭环。

调试阶段每收到一帧通过CRC校验的坐标，飞控会通过USART1 TX（PA9）以115200波特率输出一行ASCII文本：

```text
SLAM_OK,X=-123,Y=456
```

若需要停止打印，将 `Ano_Scheduler.c` 中的 `SLAM_UART2_DEBUG` 改为 `0`。

### 3.2 地面站数据 (USART2)

**帧格式：** `0x45` (帧头) + 2字节有效数据 + `0x46` (帧尾)

| 字节 | 含义 |
|------|------|
| [0] | 障碍物 x 坐标 (1~9) |
| [1] | 障碍物 y 坐标 (1~7) |

**状态：** 当前代码中地面站接收逻辑已被注释掉，障碍物改为硬编码。

## 4. 程控任务流程

由 `FcSrc/User_Task.c` 中的 `UserTask_OneKeyCmd()` 实现，通过遥控 **CH6 高位** 触发：

| 步骤 | case | 动作 | 说明 |
|------|------|------|------|
| 1 | 1 | `LX_Change_Mode(3)` | 切换为 **程控模式** (模式3) |
| 2 | 2 | `FC_Unlock()` | 解锁电机 |
| 3 | 3 | 延时 2s | 等待解锁稳定 |
| 4 | 4 | `OneKey_Takeoff(50)` | 一键起飞到 **50cm** 高度 |
| 5 | 5 | 悬停 3s | 等待姿态稳定 |
| 6 | 6 | `run_path_planner()` | **执行路径规划**：BFS + 最近邻 TSP，生成遍历所有可达格子的逐格路径 |
| 7 | 7 | 航点跟踪 | 每格发送 `Horizontal_Move(50, 25, angle)`，等待6秒后继续下一格 |
| 8 | 8 | `OneKey_Land()` | 遍历完最后一个格子后，**直接降落**（不回到起点） |

**CH6 低位：** 一键降落（随时可用）。  
**CH6 中位：** 取消任务，清零速度输出，重置任务状态。

### 4.1 路径规划算法

- **BFS 最短路径**：在每对相邻访问点之间寻找最短路径（避开障碍物）
- **最近邻 TSP**：从 `(0,0)` 出发，按最近邻策略遍历所有可达格子
- **不回到起点**：`build_full_path` 已修改为 `count - 1`，遍历完最后一个格子即结束

### 4.2 逐格移动方向映射

`Horizontal_Move` 的方向角相对于**机头正前方**：

| 方向 | angle | 网格变化 |
|------|-------|----------|
| 向前 | 0° | `row + 1` |
| 向后 | 180° | `row - 1` |
| 向右 | 90° | `col + 1` |
| 向左 | 270° | `col - 1` |

每格移动后等待 **7s**（50cm / 10cm/s = 5s + 2s 余量），然后停留 **1.5s** 检测。

## 6. 关键注意事项

1. **Horizontal_Move 是协议指令，不是直接写速度。**  
   程控模式下，直接修改 `rt_tar.st_data.vel_x/y` **不会生效**。必须通过 `LX_FC_Fun.c` 中的协议函数（如 `Horizontal_Move`、`OneKey_Takeoff`）发送指令，飞控才会执行。

2. **方向角度定义。**  
   `Horizontal_Move(dir_angle_0_360)` 中 `0` 表示 **机头正前方**（Y轴正方向），具体坐标系以飞控固件定义为准。

3. **路径规划依赖飞控光流精度。**  
   逐格移动基于相对位移（光流），每格仅 50cm，累积误差可控。如需更高精度，可在每格移动后通过树莓派坐标做闭环修正。

4. **树莓派 UART 启动延时。**  
   `Ano_Scheduler.c` 的 `Loop_50Hz` 中，上电后约 3 秒（150 * 20ms）才开启 USART3 接收中断，以避开树莓派启动时的串口冲击。

5. **调试串口输出。**  
   `Loop_20Hz` 每 200ms 通过 USART2 输出一帧 12 字节二进制数据，格式：`0xAA 0x55 | now_x(2B) | now_y(2B) | vel_x(2B) | vel_y(2B) | 0x0D 0x0A`，可用于地面站监控。

## 7. 历史修改记录

- **初始版本：** 基于 PID + 航点跟踪的路径规划方案，依赖树莓派实时坐标做闭环控制（飞起来不动）。
- **简化版本：** 弃用路径规划，改为直接调用 `Horizontal_Move(200, 10, 0)` 平移后降落。
- **当前版本（SLAM 接入准备）：** USART3 接收树莓派输出的 SLAM 坐标；路径仍使用 `Horizontal_Move` 逐格开环移动，遍历完直接降落。后续将以 SLAM 坐标实现水平位置闭环。
